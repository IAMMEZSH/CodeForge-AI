The debug loop

Compile, execute, capture the truth, then let the local model replace the whole file with a corrected version. Repeat until green or bounded.

01

Source intake

Full file from the editor, language and filename. Auto-detect uses the extension: .py .c .cpp .cxx .cc .java.

≤ 200 KB · workspace created
02

Compile

Python is interpreted. C, C++ and Java are compiled with the detected toolchain inside the session directory.

gcc · g++ · javac · 60 s budget
03

Execute

The program runs with a process-tree timeout. stdout, stderr, exit code, command line and duration are captured.

Job Objects / process groups
04

Observe

Exit code 0 means success. Any compiler error, runtime error or timeout becomes diagnostic context for the next step.

exact output · no guessing
✓
Success pathPersist report.json + final.<ext>, return every iteration record, stop immediately. No model call is made if the first run passes.
failure
continue loop
05

Diagnose

The complete source and the exact diagnostics are sent with a system prompt that demands a single fenced block containing the full corrected program.

root cause first · minimal change
06

Patch

The first fenced code block is extracted. Missing blocks or identical content stop the loop with a precise error instead of spinning.

no diff · complete replacement
07

Re-run

The corrected file is written and executed again. Steps 03–06 repeat until success or the iteration limit.

bounded · auditable · saved
