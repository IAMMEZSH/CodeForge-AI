Windows 10 / 11

FULL HOST

MinGW-w64 + Python + JDK 17. The native control center starts the server and opens an Edge app window.

:: toolchain winget install Python.Python.3.12 winget install MSYS2.MSYS2 pacman -S mingw-w64-ucrt-x86_64-gcc make :: build + launch python aux-python\bootstrap.py --all native\bin\CodeForge.exe :: server only + health java --add-modules jdk.httpserver ^ -jar server-java\build\CodeForgeServer.jar curl http://127.0.0.1:8765/api/health

Linux

FULL HOST

Debian, Ubuntu, Fedora, Arch and openSUSE. libcurl and pthreads power the core; systemd can keep it alive.

# Debian / Ubuntu sudo apt install -y build-essential cmake \ libcurl4-openssl-dev python3 openjdk-17-jdk # build + launch python3 aux-python/bootstrap.py --all python3 aux-python/bootstrap.py --run xdg-open http://127.0.0.1:8765/console/ # verify + inspect listener curl -s http://127.0.0.1:8765/api/health ss -ltnp | grep 8765
libcurlprocess groupssystemd
Also: ./build.sh → native/bin (CMake route, same layout)

macOS

FULL HOST

Apple Silicon and Intel. Homebrew supplies CMake and JDK 17; the runtime resolver picks arm64 or x64.

# Xcode CLT + Homebrew xcode-select --install brew install cmake python@3.12 openjdk@17 python3 aux-python/bootstrap.py --all python3 aux-python/bootstrap.py --run open http://127.0.0.1:8765/console/ # verify + inspect listener lsof -nP -iTCP:8765 -sTCP:LISTEN curl -s http://127.0.0.1:8765/api/health
arm64x64launchd
Gatekeeper: xattr -dr com.apple.quarantine native/bin/CodeForgeCore

Android

TWO ROUTES

Termux can host the full stack. The Kotlin WebView client connects to a server on the device or LAN.

# Termux host pkg install python clang make cmake \ libcurl openssl openjdk-17 git termux-wake-lock python aux-python/bootstrap.py --all # thin client cd mobile/android && ./gradlew assembleDebug adb install -r app/build/outputs/apk/debug/app-debug.apk # USB link to a LAN host adb reverse tcp:8765 tcp:8765
TermuxKotlin / WebView10.0.2.2
ARM64: managed runtime available. Other ABIs: build llama.cpp locally and write runtime/runtime.json. See PLATFORMS.md.

iOS / iPadOS

THIN CLIENT

The SwiftUI WKWebView client is the recommended route. Hosting inside iSH is experimental and memory-bound.

# Swift thin client brew install xcodegen cd mobile/ios && xcodegen generate xcodebuild -list -project CodeForge.xcodeproj xcodebuild -project CodeForge.xcodeproj \ -scheme CodeForge -configuration Release build # iSH host (experimental) apk add python3 clang cmake curl-dev openjdk17
